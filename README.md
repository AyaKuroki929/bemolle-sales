# ベモーレ 売上日報システム

紙の日計表（1日1枚の手書き）を置き換えるシステム。
タイムカード（bemolle-timecard）と同じ作り＝ GAS（Apps Script）＋ Google スプレッドシート ＋ iPad の画面。

## できること

- **1会計＝1入力**：顧客・担当・施術・契約・物販・定期便・その他を1画面で登録
- **支払いを分けられる**：現金＋JMSのように複数行。**「後日」にすると未収として残り、入金した日に消し込む**
- **過去の日付もそのまま入力・修正・追加できる**（日付を選ぶだけ。締めのロックなし）
- **在庫払出**：売上でない持ち出しを「サロン使用／黒木購入」の2択で記録
- **インセンティブ自動計算**：報酬規定2025-04-03どおりに自動。彩さんの手計算が不要になる
- **税理士向けCSV**：税率別（8%/10%）・支払方法別・明細のCSVを1クリックで書き出し

## 日付の入れ方（重要）

**会計の日付は「決済日（お金が動いた日）」で入れる。** 紙の日計表と同じ運用。

- 先に契約だけ取って、支払いが後日になった場合も、**決済した日に1行書く**（売上もインセンティブもその日に付く）
- **一部だけ後日にいただく場合も、インセンティブは契約した日に全額付く**（未収の分も含めて計算する。2026-09-17 彩さん決定）。月をまたいでも契約件数のカウントは契約した月に入る
- そのため、**スタッフが出勤していない日にも行が立つ**ことがある（前に取った売上の決済がその日に来たケース）。日当だけはタイムカード側で出勤日に紐づくので、日当のない日にインセンティブだけが付くのは正常

## インセンティブの計算ルール（報酬規定2025-04-03 準拠）

| 区分 | 計算 |
|---|---|
| 施術（全身） | 1回 ¥3,000・**1日3件まで** |
| 施術（半身・セルマン） | 1回 ¥2,250・**1日4件まで** |
| 施術（プラペン） | 1回 ¥1,800・**1日5件まで** |
| 施術（部位） | 1部位 ¥500 |
| 物販 | 税抜の10% |
| 定期便 | 税抜の5%（**初回は対象外**・2ヶ月目以降） |
| 契約 | 月内の件数で 1〜2件目5% / 3〜4件目8% / 5件目以降10% |
| ラジショット・部位チケット | 5%固定・**契約の件数に数えない** |
| 折半 | 予約を取った人（アポインター）と施術した人（クローザー）で施術インセンティブを半分ずつ |

- 率で出す分（契約・物販・定期便）の端数は**切り捨て**（紙の運用に合わせた。例：151,620×8%＝12,129.6→12,129）
- インセンティブは**税抜**で計算
- 日当（¥5,000）はタイムカード側で管理。この画面では扱わない

## 検証

`node test_incentive.js` で、2026年8月の紙（実物）の余白に手書きされた金額と計算結果が一致することを確認できる。
契約①〜⑥（14,364／9,900／24,192／12,129／28,728／30,240）・物販・定期便・1日上限・折半の全項目が一致。

## セットアップ

1. Googleスプレッドシートを新規作成（名前：ベモーレ売上日報）
2. 拡張機能 → Apps Script を開く
3. `Code.gs` の中身を全部貼り付けて保存
4. エディタで `initSheets` を1回実行（シートと初期マスタが作られる）
5. デプロイ → 新しいデプロイ → ウェブアプリ（実行：自分／アクセス：全員）→ URLをコピー
6. `index.html` の `API_URL` にそのURLを貼る
7. `index.html` を GitHub Pages に置いて、iPadのホーム画面に追加
8. 管理者PINを変更する（初期値1234。設定タブ → PIN欄 → `changePin`）

## 使い始めるとき

- 設定タブで**商品マスタ**（商品名・税率・税抜単価）を登録する。定期購入の商品もここに入れる
- メニューマスタは初期値（全身・半身・下半身・上半身・セルマン・プラペン・部位・ラジショット・体験・フェイシャル）が入っている。区分が違うものは直す
- スタッフは「インセンティブ対象」のチェックで分ける（黒木は対象外）

## シート構成

| シート | 内容 |
|---|---|
| 会計 | 1会計1行（日付・顧客・担当・アポインター・合計） |
| 明細 | 会計の中身（施術/契約/物販/定期便/その他/調整） |
| 入金 | 支払い（複数行可・未収の状態を持つ） |
| 在庫払出 | サロン使用／黒木購入 |
| 商品マスタ・メニューマスタ・スタッフ | 選択肢 |
| アーカイブ | 削除したデータの退避先（消えっぱなしにしない） |

## 注意

- 削除には管理者PINが要る。削除したものはアーカイブシートに残る
- 回数券の消化は金額0のまま登録する（売上は契約時に計上済み・インセンティブは付く）
- 解約でインセンティブを返す場合は「調整」でマイナス金額を入れる

## うらかたさんから取り込んで支払方法だけ入れる（2026-09-18 の設計）

紙の日計表をやめ、**売上はうらかたさんに入れたものを使う**。足りない情報（税率・支払方法・未収）だけをこの仕組みで補う。

1. `python3 setup_sheet.py` … スプレッドシートを作る（初回のみ。IDは sheet_id.txt に保存）
2. うらかたさんの売上管理からCSVを取り出す（Chromeで読む。手順は memory の reference_urakatasan_data_access.md）
3. `python3 import_sales.py <物販CSV> <サービス契約CSV>` … 日付＋お客様でまとめて「会計」「明細」に入れる。入金は空のまま
4. 画面の「支払入力」タブで、お客様ごとに**現金／JMS／Square／振込のボタンを1回押すだけ**。分割や後日は「分けて払う」から

税率は商品マスタ（products.json＝Notionの棚卸しページが原本）から自動で付く。
定期便は「日付が1日 かつ 金額が定価×数量の90%」で自動判定し、インセンティブ5%として扱う。

## タイムカードとの連携

`TIMECARD_ID`（Bemolle タイムカードのスプレッドシート）のタブ「氏名_YYYY-MM」を直接読み、
出勤日数と日当の合計を取る。タイムカード側は何も変えない。

集計タブで **日当 ＋ 特別日当 ＋ インセンティブ ＝ 支給合計** が1枚で出る。
タイムカードが読めない月は日当0で表示し、画面は止めない。
